# 登录图形验证码 —— 前端对接文档

> 负责人：后端 D → 交付：前端 A
> 归属模块：用户认证（`/api/user`）
> 后端已完成并合入 `dev-D`，前端改造完成后登录功能即恢复可用。

---

## 1. 背景

为防止脚本批量试密码，登录接口新增了**图形验证码**强制校验：

- 登录前必须先调 `GET /api/user/captcha` 拿一张验证码图片；
- 用户看到图片输入 4 位字符，提交登录时随表单一起传给后端；
- 验证码**一次性有效**（无论对错都作废）、**5 分钟过期**、**不区分大小写**。

后端已就绪，登录页只需按下面步骤改造。改动集中在 2 个文件：
`frontend/src/api/user.js` 和 `frontend/src/views/LoginView.vue`。

## 2. 交互流程

```
进入登录页 ──> GET /api/user/captcha ──> 展示图片(记录 captcha_id)
    │
用户输入账号/密码/验证码 ──> POST /api/user/login
    │                        { username, password, captcha_id, captcha_code }
    ├── code=0   登录成功（原逻辑不变）
    ├── code=1010 验证码错误/过期 ──> 必须重新获取验证码并清空输入框
    └── 其他错误（1001 密码错 / 1004 限流）──> 同样建议刷新验证码
```

要点：**只要登录失败，当前验证码就已作废，必须刷新**（后端一次性消费）。

## 3. 后端接口契约

### 3.1 获取验证码 `GET /api/user/captcha`

无需登录、无请求参数。响应 `data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `captcha_id` | string(32) | 本次验证码标识，登录时原样传回 |
| `image` | string | SVG 图片的 base64 data URL，`<img :src>` 直接绑定 |
| `expires_in` | number | 有效期秒数（当前 300） |

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "captcha_id": "9f2c1a7e6d3b4c8fa1b2c3d4e5f60718",
    "image": "data:image/svg+xml;base64,PHN2ZyB4bWxucz0iaHR0...",
    "expires_in": 300
  }
}
```

### 3.2 登录 `POST /api/user/login`（请求体变更）

在原有 `username`、`password` 基础上**新增 2 个必填字段**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `username` | string | 原有 |
| `password` | string | 原有 |
| `captcha_id` | string | 获取验证码时返回的标识 |
| `captcha_code` | string(4) | 用户输入的 4 位验证码，不区分大小写 |

**错误码新增 `1010`**：验证码错误或已过期（msg 可直接 toast）。
其余原有错误码不变：`1001` 账号或密码错误、`1004` 登录失败次数过多。

## 4. 前端改造步骤

### 4.1 `src/api/user.js`：新增获取验证码方法

```js
// 获取登录图形验证码：返回 { captcha_id, image, expires_in }
export const getCaptcha = () => request.get('/user/captcha')
```

### 4.2 `LoginView.vue`：表单加验证码行

`<script setup>` 部分：

```js
import { ref, reactive, onMounted } from 'vue'
import { getCaptcha } from '@/api/user'   // 或经 store，二选一

const form = reactive({ username: '', password: '', captcha_code: '' })
const captchaId = ref('')       // 本次验证码标识，提交时传回
const captchaUrl = ref('')      // 图片 data URL

// 拉取/刷新验证码
async function refreshCaptcha() {
  const { data } = await getCaptcha()
  captchaId.value = data.captcha_id
  captchaUrl.value = data.image
}

// 进入登录页自动加载一次
onMounted(refreshCaptcha)
```

`submit()` 中把验证码一并提交（store.login 透传即可）：

```js
await store.login({
  ...form,
  captcha_id: captchaId.value,
})
```

表单校验规则补一条：

```js
captcha_code: [{ required: true, message: '请输入验证码', trigger: 'blur' }]
```

`<template>` 部分，在密码输入框后面加一行（输入框 + 图片 + 点击刷新）：

```html
<el-form-item prop="captcha_code">
  <div class="captcha-row">
    <el-input v-model="form.captcha_code" placeholder="验证码（不区分大小写）" maxlength="4" clearable />
    <img
      class="captcha-img"
      :src="captchaUrl"
      title="看不清？点击刷新"
      @click="refreshCaptcha"
    />
  </div>
</el-form-item>
```

```css
.captcha-row {
  display: flex;
  gap: 10px;
  width: 100%;
}
.captcha-img {
  height: 40px;
  border-radius: 6px;
  cursor: pointer;
  flex-shrink: 0;
}
```

### 4.3 登录失败后的验证码刷新（重要）

登录失败（任何错误码，尤其 `1010`）后当前验证码已作废，需要在 `catch` 里刷新：

```js
try {
  await store.login({ ...form, captcha_id: captchaId.value })
  // ...成功跳转
} catch {
  form.captcha_code = ''   // 清空已作废的输入
  refreshCaptcha()         // 重新拉一张
}
```

> `request.js` 会统一弹出错误 msg，这里无需重复提示。

## 5. 自测清单

- [ ] 进入登录页自动显示验证码图片，点击图片可刷新
- [ ] 不填验证码提交 → 前端表单校验拦截
- [ ] 验证码填错 → 提示「验证码错误或已过期」，图片自动刷新
- [ ] 验证码填对 + 密码正确 → 登录成功跳转
- [ ] 验证码填对 + 密码错误 → 提示「用户名或密码错误」，验证码已刷新
- [ ] 同一张验证码第二次提交 → 返回 1010（一次性有效）
- [ ] 验证码忽略大小写（图上 `Ab3D`，输入 `ab3d` 也能通过）
- [ ] 图片 5 分钟后过期，重新点击可获取新图

## 6. 注意事项

1. `image` 是 `data:image/svg+xml;base64,...` 格式，`<img>` 直接绑定即可，**不要**再拼 base64 前缀；
2. `captcha_id` 每次刷新都会变化，提交时务必用**最新一次**的 id；
3. 后端验证码存于内存，服务重启后旧 `captcha_id` 全部失效——前端遇到 1010 刷新重试即可，无需特殊处理；
4. 注册接口不需要验证码，只登录需要。
